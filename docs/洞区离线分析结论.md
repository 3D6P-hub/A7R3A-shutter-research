# libObj.so 洞区离线分析结论（2026-11-24，守则v1.1 15.1/15.2 实践）

## 根因实锤（TsOtOS_2_init 为何开机被调）
- TsOtOS_2_init val=0x53cf5b size=598，是 **.dynsym 导出函数**；名字串在 .dynstr@0x2a942。
- 全文件指向 0x53cf5b 的指针**仅 1 处：0xf068（.dynsym/重定位区）**，不在 .init_array（实测 False）。
- 结论：开机被 **dlsym("TsOtOS_2_init") 按名字动态调用**（im.elf 或其他库）。静态地址引用扫描查不到名字调用 → 漏判。
- **铁律：.dynsym 导出函数绝不能当洞（会被按名动态调用）。**

## libObj.so 段布局
- LOAD[0] RX: off=0 vaddr=0 filesz=0x11a50e4（整段 RX，含 .rodata）。
- .text: 0x104070 size=0xbf03cc（止 0xcf443c）。
- .rodata: 0xcf4448 size=0x34b606。
- .init_array: off=0x11a50e4 size=0x434（269 项，不含 TsOtOS_2_init）。

## 洞区扫描结论
- **.text 代码区零隙 >=64B：0 个**（代码 100% 密集，无缝可钻）。
- RX 段 >=128B 零区共 56 个，**全在 .rodata 数据区**；最大 8 个均有指针引用（3~116 处），疑为零初始化缓冲区/表，被代码引用 → 写代码会破坏数据，不安全。
- **libObj.so 无现成安全纯零洞。**

## 对固化的指导
1. **首选 RAM 注入**（无需洞，零风险）。
2. 若固化：覆盖"非导出 + 不在 init 路径 + Unicorn 跑 boot 实证不执行"的函数，而非找零洞。
3. 必须完整 Unicorn 开机仿真验证（ref-bionzx tools.research.run_nflasha1_boot / UnicornMachine）。
4. 候选洞多路扫描须含：bl/blr、ldr+add、绝对指针、movw/movt、.init_array、**自定义 init 表**、**.dynsym 导出 + dlsym 名字调用**。

## Unicorn 实证（a7_unicorn_init_trace.py，守则15.1）
- 仿真 .init_array 全部 269 个初始化函数（import/PLT 处停止）。
- **TsOtOS_2_init(0x53cf5a) 未被 init_array 执行 = False**，坐实外部 dlsym 按名调用。
- 15 个大候选洞初始化均未执行——**但它们在 .rodata 数据区，有指针引用（零初始化数据缓冲），写代码会破坏数据引用，仍不安全**。
- 局限：init 仿真仅 traced 939 字节（到 import 即停），非完整开机仿真；完整 boot 需仿真 im.elf→libObj 全调用链（大工程，ref-bionzx UnicornMachine/run_nflasha1_boot）。
- **结论：.rodata 零块"初始化不执行"≠安全洞（是被引用的数据）。libObj 无安全代码洞。**
