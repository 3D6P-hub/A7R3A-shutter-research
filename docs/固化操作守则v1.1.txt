A7R3A 固化/刷机操作守则（避免变砖）
供操作 AI 执行任务时逐条遵守；任何条款冲突时，第 0 节优先。
版本 1.0 · 2026-11-24 · 基于本次 TsOtOS_2_init@0x53cf5a 变砖事故复盘
================================================================
【0. 总原则】
0.1 宁可不做，不要错做。不做 = 零损失；做错 = 送修。
0.2 只读优先。任何写入之前，必须先有备份、改动清单、回滚方案。
0.3 一次只改一处。一次写一台、一处字节区域、一个功能目标。
0.4 相机处于异常状态（卡死 / 崩溃循环 / 画面异常 / 枚举异常）=> 禁止写入。
0.5 以实机现象为准。AI 推断只是假设，不是结论。
0.6 备份、清单、校验有一项不齐，立即停止，先补齐。
【1. 变砖分级与处置】
1.1 档位1 硬砖：红灯/黑屏，任何键无反应 => 停止一切写入，送修。
1.2 档位2 软砖：菜单/MSC/USB 还有一路活 => 只读诊断，走回滚。
1.3 档位3 功能异常：能拍但行为异常 => 记录现象，回滚或保留（用户决定）。
1.4 出现档位1/2 迹象时，禁止"再补一个洞补丁"式叠加修复。
【2. 静态分析红线（本次事故直接主题）】
2.1 ".init_array 里没有" ≠ "开机不被调用"。
    索尼/SDK 有自定义初始化注册表（函数指针表）藏于数据段，
    不在标准 .init_array。TsOtOS_2_init@0x53cf5a 就是实锤：
    全程 .text 无 bl 调用、无 ldr+add 取址、无绝对指针引用、
    不在 .init_array，被判"死代码"，结果开机被调用，im.elf 秒死。
2.2 候选洞区必须通过全部多路证据一致否定，才能当 cave：
    (a) BL/BLX 直接调用；
    (b) PC 相对 ldr + add 取址；
    (c) 绝对地址字（LE 32 位 / Thumb 地址右移形式）；
    (d) MOVW/MOVT 构造；
    (e) 数据字池 / .rodata 字；
    (f) .init_array 及所有自定义初始化注册表；
    (g) 符号表 / 字符串表引用。
    任一路查不清楚 => 该区域不得使用。
2.3 必须用 Ghidra XREF + 自写扫描脚本双重验证；两结果不一致 => 停。
2.4 任何"死代码判定"都是最危险的中间结论；洞区选错 = 变砖。
    未被双工具证实为零引用的区域，一律按"活体"处理。
2.5 洞区容量 >= stub 大小 + 至少 64 字节边距，且不得跨越相邻函数。
2.6 若表项指针要重定向（init 表指向空桩），写表项之后必须先拔电池
    冷启动验证整机能进菜单，再启用其余补丁。
2.7 验证 stub 时，先验证"跳过"（直接返回）再验证"跳了有用"。
【3. n15 存储介质特性（本机实证）】
3.1 n15 = e2compr 压缩 ext2（blocksize 1024，ro_compat=0x3）。
    n15.bin 的文件偏移 ≠ 磁盘扇区偏移。
3.2 禁止用 dd 按 dump 偏移裸写 /dev/nflasha15。
3.3 固化写入只允许以下两种：
    (a) 文件级写入：挂载后的目标文件 open(O_RDWR) + pwrite，
        尺寸必须与原文件一致；
    (b) e2compr 感知重打包工具（簇尺寸可变）。
3.4 CP (nflasha3) 的 +0x10200 偏移是 CP 专用，绝不用于 n15。
3.5 写前：dd 备份原段 + SHA256；写后：读回比对字节 + SHA256。
【4. 写入纪律流程】
4.1 先读（备份原段+校验）→ 生成改动清单 → 执行写 → 读回比对 →
    sync → 拔电池 >= 60 秒 → 开机验证。
4.2 改动清单一式两份（相机侧清单 + 文本记录），每项必须写：
    分区 / 文件 / 地址(文件偏移+物理偏移) / 原值 / 新值 / 原因 / 回滚值。
4.3 一次只固化一个补丁；若必须写多处，分批次写，每批读回比对。
4.4 禁止在有未验证改动存在的情况下再叠加第二个改动。
4.5 相机任何异常状态下（见 0.4），只读，绝不写。
【5. RAM 优先原则（固化的前置条件）】
5.1 任何补丁先用 RAM 注入验证（/proc/PID/mem 或服务工具注入），
    RAM 改动 = 拔电池即清，是最安全形态。
5.2 RAM 注入后必须通过完整回归：
    菜单可进 / 曝光·ISO·快门三项显示 / 机械快门 / 电子快门 / 录像 /
    对焦音 / 拔电池冷启动回归。
5.3 任一项不通 => 补丁本身有问题，禁止转 flash 固化。
5.4 RAM 回归全过后，才允许进入第 11 节固化流程。
【6. 固化后第一次开机（现场验证）】
6.1 相机就在手边开机；自检→菜单→拍摄界面一气呵成，逐项看：
    自检不崩、菜单可进、三项信息显示、机械快门、电子快门、
    录像启动、菜单滚动、拔电池再开机。
6.2 任一项异常 => 立刻回滚；禁止"再开一次试试运气"。
6.3 冷启动（拔电池）>= 3 次，全部正常才算固化完成。
6.4 出现崩溃/红灯/自行重启 => 记下次数；>= 3 次即进入第 9 节停止条件。
【7. 回滚预案（先备好，再下笔）】
7.1 回滚写入器（按原值写回的脚本）必须先于固化写好并自检
    （语法检查 / 空跑 / 备用分支测试）。
7.2 回滚 = 原字节原样写回；禁止图省事"删文件重刷"（/usr 无法用
    文件系统操作恢复，因为原文件只有同尺寸覆盖一种安全姿势）。
7.3 回滚后拔电池 >= 5 分钟再开机验证。
7.4 回滚如果只写一处没办成，就对照清单逐处恢复，不遗漏。
【8. 红线分区】
8.1 nflasha5 / nflasha7（启动链 WBI1 / rootfs）—— 任何情况下不碰。
8.2 BootROM / SECURE / 签名分区 —— 不碰。
8.3 sabin（DSP 主固件）—— 不碰。
8.4 nflasha3（CP）—— 仅限已验证流程，必须用 +0x10200 偏移纪律，
    且有 CP 备份 + 读回验证。
8.5 n15 —— 文件级同尺寸覆盖；不使用 raw dump 偏移。
8.6 单字节失误 = 整机送修；下笔前把清单交给第二个流程复核。
【9. 停止条件（出现任一 => 停写、纯只读、联系备份）】
9.1 连续 3 次开机无法进菜单。
9.2 崩溃 / 红灯闪 / 秒级死循环 / 自停机。
9.3 USB 异常：仅枚举充电模式(054C:0994)、服务模式 STALL、
    pipe error、任何预期外 PID。
9.4 写后读回与预期不符（哪怕差一个字节）。
9.5 任何"好像是这样"但没经实机/读回验证的结论。
9.6 对某个偏移动机存在任何怀疑 => 停，去查，不写。
【10. AI 协作守则】
10.1 AI 给的字节/偏移/洞区，必须机械校验后才执行：
     段边界 / patch 长度 / 读回比对 / 与 dump 逐字节一致性。
10.2 多个 AI 意见冲突 => 优先级：实机现象 > dump 字节 > 文档 > 推理。
10.3 AI 判定"死代码/零引用/无人调用" => 默认不可信，必须双工具验证。
10.4 含 open(...O_RDWR) / dd / /dev/nflasha / 写入指令的操作前，
     AI 必须先输出：影响评估 + 回滚方案 + 清单，获人确认后才执行。
10.5 查不到的就说查不到；严禁编造偏移、字节、表项地址。
10.6 AI 必须随时能给出"改了哪些字节"的完整清单，否则不允许继续。
【11. 固化标准流程（正确版 checklist）】
第 1 步 确认 dump 与 SHA256 齐全，备份在手。
第 2 步 补丁先过 RAM 验证（第 5 节），全过才可固化。
第 3 步 生成改动清单，清单交第二人/第二流程复核。
第 4 步 备份原段（dd + sha256）。
第 5 步 文件级 pwrite 写入，尺寸校验。
第 6 步 读回比对，逐字节一致。
第 7 步 sync。
第 8 步 拔电池 >= 60 秒。
第 9 步 开机验证（第 6 节清单）。
第 10 步 冷启动 >= 3 次。
第 11 步 回归：对焦音/菜单音/录像/机械+电子快门。
第 12 步 清单归档 + 更新固化记录文档。
任一 gate 不通过 => 停在该步，不进下一步。
【12. 变砖送修准备（现场操作）】
12.1 先拔 SD 卡备份照片；dump/清单/日志打包。
12.2 手机录像：开机→M 画面→约 2 秒红灯→重启 ×6→停机。
12.3 带上：相机、购买凭证、原装电池、本守则复盘章节。
12.4 如实告知维修方：仅改 n15/libObj.so 相关字节，启动链(nflasha5/7)
     完好，症状=开机数秒崩溃/红灯/循环停机，USB 仅充电模式。
12.5 优先索尼直营/授权维修；失败再找芯片级实验室（带 dump 整盘复原）。
【13. 附：本次事故复盘（TsOtOS_2_init@0x53cf5a）】
13.1 现象：开机→M 拍摄界面→约 2 秒崩溃→右下角红灯闪→重启；
     连续约 6 次后彻底停机；循环中 on/off 无效；菜单/曝光死；
     AF 正常；USB 仅枚举充电模式(054C:0994)；服务模式 STALL/pipe error。
13.2 根因（高度可信假设，送修/拆字节后确认）：
     M5 固化选用 TsOtOS_2_init@0x53cf5a 作洞区（cave），
     静态扫描判定"全程 .text 无 bl、无 ldr+add、无绝对指针、
     不在 .init_array => 死代码"。
     实际该函数为开机初始化函数，被索尼自定义初始化注册表调用；
     开机早期执行到 cave 中的 stub → 崩溃链 → im.elf 挂死 →
     USB 应用 gadget 无法初始化 → 仅剩启动链/充电 gadget。
13.3 教训：
    (1) .init_array 不是全部，自定义注册表必须全量定位+交叉验证；
    (2) "全程静态零引用"≠"运行时"；
    (3) 洞区选择 = 补丁正确性的一半；
    (4) RAM 验证不过绝不固化（本次 RAM 阶段若已彻底验证 boot 冷启动，
        事故可以在送修前被发现）；
    (5) 写前清单要写清"为什么这个洞安全"，没写清=不安全。
13.4 将来再固化：从 0 重做洞区选择，补齐第 2 节全部多路证据，
     先 RAM 完整回归，再固化，且固化后现场 watch 10 分钟。
【14. 附：名词表】
MSC / Mass Storage Mode：相机作为 U 盘枚举；进服务模式的前提。
充电模式 054C:0994：仅充电接口 gadget，不带数据。
service mode：相机的服务通道（senser/Jiritsu），本机依赖 MSC。
raw 裸写：直接写分区（/dev/nflashaX）；n15 压缩 ext2 下禁止。
文件级 pwrite：对挂载后的文件按偏移写，尺寸不变。
e2compr：压缩 ext2，blocksize 1024，n15 使用。
.init_array：标准初始化表，常被误认为唯一的初始化来源。
