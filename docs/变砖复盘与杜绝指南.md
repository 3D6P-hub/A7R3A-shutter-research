# A7R3A 变砖复盘与杜绝指南

日期：2026-11-24 ｜ 机型：索尼 ILCE-7RM3A（CXD90045 / BIONZ X）

---

## 一、为什么变砖（根因）

**直接原因：M5 固化把钩子写进了 libObj.so 闪存，选错了"死洞"。**

1. M1 阶段用 **RAM 注入**（改 /proc/PID/mem）成功实现电子快门发声，拔电池即恢复，零风险。
2. M5 想"固化"（写闪存让补丁永久生效），需要找一段开机不会执行的"死代码"区域（cave）放钩子。
3. 选了 `TsOtOS_2_init @ 0x53cf5a`。判据是**静态零引用**：
   - 全 .text 无 `bl` 调用它；
   - 无 `ldr + add` 取址；
   - 无绝对指针引用；
   - 不在 `.init_array`。
   → 据此判定"死代码"。
4. **但这个判断错了**：`TsOtOS_2_init` 是 `_init` 后缀函数，**开机时实际被调用**——经一条静态扫描没覆盖的路径（运行时计算的函数指针 / 自定义 init 表 / 初始化框架）。
5. cave 被曝光 stub 覆盖后，**开机执行到它就跑飞** → 主程序 `im.elf` 挂起 → 相机卡在拍摄界面（只显示 M）/重启循环。

**核心教训：静态零引用 ≠ 死代码。`_init` 函数尤其危险，开机初始化路径必须单独验证。**

## 二、为什么软件救不回

- 主程序 `im.elf` 在**开机很早期**就挂起，**还没来得及启用 USB 大容量(0D99)/服务(0336)模式**。
- 相机只枚举出内核默认的**充电 HID(0994)**。
- 大容量捕捉：0D99/0336 根本不出现，抓不到。
- 直通服务模式（StartSenser vendor 请求）：相机固件砖机态**主动 STALL 拒绝**（libusb-win32/WinUSB/libusbK 三种驱动一致报 I/O / Pipe error）——负责响应的服务程序没跑起来。
- 按键组合强制服务/更新模式：A7R3A 无 documented 组合，试遍无效。
- 强制服务标记 `/setting/sen/smode="UU"` 存在，但在内部 nflasha2，**砖机态无连接写不进**（死结）。

→ 软件层无解，只能**底层重刷**（售后专业工具 / UART 串口 / Pico BootROM 注入）。

---

## 三、为什么不能用 SD 卡触发救援

参考工程 E0413（CXD90045 更新模式离线分析）明确确认：

1. **无 SD 卡更新触发**：所有更新模式标记路径都在内部 `/setting/...`（nflasha2），**不存在 SD 卡 `\updater\mode` 检查**。
2. **updater ramfs 不挂 SD**：更新模式的 initramfs 脚本**从不挂载 SD 卡**；`is_valid_boot.sh` 引用的 `ud_get_boot_device.elf` 缺失，且其调用被注释掉。
3. **更新模式进入流程**：app 写 `/setting/updater/mode` → loader 读取 → 进 updater。砖机态 app 挂起，**写不进这个标记**。
4. **SD 卡 boot（MLV2.TAR）是 mod 加载机制**（ILCE-6400A 验证），**不是救援通道**，且依赖正常启动的 mod loader——砖机态用不了。

→ **SD 卡无法在砖机态触发任何救援模式**。这是固件设计决定的，不是操作问题。

## 四、以后怎么杜绝（固化铁律）

### 选死洞
- **绝不选 `_init` / 初始化相关函数**做 cave，即使零静态引用。
- 死洞验证必须**多角度**：bl 扫描 + ldr+add 取址 + 绝对指针 + `.init_array` + **自定义 init 表** + **运行时函数指针** + **实机/模拟器开机路径验证**。
- 优先选**纯填充零区**（RX 段尾部全零 padding），而非任何函数体。

### 验证
- **固化前必须模拟器（Unicorn/QEMU）跑开机路径**，确认 cave 开机不被执行。
- 静态分析只是初筛，**开机路径动态验证才是判据**。

### 写入
- **优先 RAM 注入**（不落盘、拔电池即恢复、零风险）；固化只在确有必要时做。
- **分步固化**：写一处 → 冷启动验证正常 → 再写下一处。**绝不一次写多处**。
- 写闪存前**确保回滚通道在线可用**（MSC/senser 能连），并**先验证回滚脚本能跑通**。
- **单分区原则**：只改 n15（/usr）。**绝不碰** n5（bootloader）/ n7（内核根文件系统）/ **0x2C000 引导头**。

### 兜底
- 每次固化前**完整备份目标分区**（SHA 校验）。
- 备好**硬件救援预案**（UART 触点位置 / Pico 工具），不要等砖了才查。

---

## 五、恢复后重做电子快门声的原则

1. **首选 RAM 注入**：每次开机注入一下，拔电池即恢复，**永不砖**。代价是每次要连电脑注入。
2. 若要固化：严格按第四节铁律，**模拟器验开机路径 + 实机验证死洞 + 分步写 + 回滚在线**。
3. 声音方案沿用已验证的 kind8 链路（曝光 flag → UI worker → ObjMsg kindId=8 → CP 发声），kind4/7 对焦音保持不变。
